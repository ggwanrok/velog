<p>인공지능은 <strong>데이터에서 반복되는 패턴을 찾아 새로운 데이터를 설명하거나 예측하는 기술</strong>이다.<br />그런데 현실의 데이터는 언제나 깔끔하지 않다. 같은 조건에서 다시 측정해도 값이 달라지고, 일부 데이터만으로 현실 전체를 완벽히 설명할 수도 없다.</p>
<p>예를 들어 기온, 습도, 가격, 요일을 이용해 다음 날의 아이스크림 판매량을 예측하는 AI를 만든다고 해보자.</p>
<p>모델을 학습시키기 전에 우리는 먼저 이런 질문을 해야 한다.</p>
<ul>
<li>판매량 데이터는 어떤 모양으로 분포하는가?</li>
<li>평균 판매량은 얼마이고, 날마다 얼마나 크게 달라지는가?</li>
<li>기온과 판매량은 정말 관련이 있는가?</li>
<li>높은 상관관계가 곧 인과관계를 의미하는가?</li>
<li>작년 여름 데이터로 앞으로의 판매량까지 예측해도 되는가?</li>
<li>새 모델의 정확도가 1% 높아졌다면 정말 더 좋은 모델이라고 말할 수 있는가?</li>
</ul>
<p>이 질문에 답하기 위해 필요한 언어가 바로 <strong>통계학</strong>이다.</p>
<p>이번 글에서는 하나의 AI 예측 문제를 따라가며 다음 흐름을 정리한다.</p>
<pre><code class="language-text">데이터를 정의한다
→ 데이터의 모습을 이해한다
→ 일부 데이터로 전체를 추론한다
→ 변수 사이의 관계를 찾는다
→ 관계를 이용해 예측한다
→ 모델이 정말 유효한지 검증한다</code></pre>
<hr />
<h1 id="1-ai가-학습할-데이터를-먼저-정의하자">1. AI가 학습할 데이터를 먼저 정의하자</h1>
<p>아이스크림 판매량을 예측하려면 먼저 어떤 데이터를 사용할지 정해야 한다.</p>

</tr>
</thead>
<tbody><tr>
<td>기온</td>

</tr>
<tr>
<td>습도</td>
<td>70%</td>
<td>입력값</td>
</tr>
<tr>

</tr>

<p>머신러닝에서는 입력으로 사용하는 변수를 <code>Feature</code>, 예측하려는 결과를 <code>Target</code> 또는 <code>Label</code>이라고 부른다.<br />통계에서는 각각 <strong>독립변수</strong>와 <strong>종속변수</strong>라는 표현을 주로 사용한다.</p>
<pre><code class="language-text">기온, 습도, 가격, 요일
→ 독립변수
→ Feature
→ X

판매량
→ 종속변수
→ Target
→ Y</code></pre>
<p>하지만 모든 변수를 같은 방식으로 다룰 수 있는 것은 아니다.<br />기온과 판매량은 숫자의 크기와 차이에 의미가 있지만, 요일은 숫자로 바꿔도 그 크기 자체에는 의미가 없다.</p>
<p>월요일을 1, 화요일을 2, 수요일을 3으로 표현했다고 해서 수요일이 월요일보다 세 배 크다는 뜻은 아니다.</p>
<p>이처럼 변수는 무엇을 측정했는지에 따라 서로 다른 성격을 가진다.</p>
<h2 id="변수의-측정-척도">변수의 측정 척도</h2>

</tr>

<p>척도를 구분하는 이유는 사용할 수 있는 분석 방법이 달라지기 때문이다.</p>
<p>예를 들어 고객 등급이 <code>BASIC &lt; SILVER &lt; GOLD &lt; VIP</code> 순서를 가진다고 해도, VIP가 BASIC보다 정확히 네 배 높은 등급이라고 해석할 수는 없다. 반면 판매량이나 가격은 두 배, 절반과 같은 비율 비교가 가능하다.</p>
<h2 id="범주형과-수치형">범주형과 수치형</h2>
<p>실무에서는 변수를 크게 범주형과 수치형으로도 구분한다.</p>
<p><strong>범주형 변수</strong>는 어떤 그룹에 속하는지가 중요하다.</p>
<pre><code class="language-text">요일
지역
상품 종류
고객 등급</code></pre>
<p><strong>수치형 변수</strong>는 숫자의 크기와 계산에 의미가 있다.</p>
<pre><code class="language-text">기온
가격
판매량
습도</code></pre>
<p>수치형 변수는 다시 셀 수 있는 <strong>이산형 변수</strong>와 연속적으로 측정되는 <strong>연속형 변수</strong>로 나뉜다.</p>
<pre><code class="language-text">이산형
→ 판매 건수, 불량 개수, 방문 횟수

연속형
→ 기온, 키, 시간, 거리</code></pre>
<p>이 구분은 단순한 용어 정리가 아니다.<br />변수의 성격을 잘못 이해하면 평균을 내서는 안 되는 값에 평균을 내거나, 순서가 없는 범주를 크기 관계처럼 모델에 입력할 수 있다.</p>
<blockquote>
<p>좋은 분석은 공식을 고르는 것부터 시작하지 않는다.<br />무엇을 측정했고, 그 값이 어떤 의미를 가지는지 정의하는 것부터 시작한다.</p>
</blockquote>
<hr />
<h1 id="2-모델링-전에-데이터의-모습을-이해하자">2. 모델링 전에 데이터의 모습을 이해하자</h1>
<p>변수를 정했다면 곧바로 모델을 학습시키는 것이 아니라 먼저 데이터를 살펴봐야 한다.</p>
<p>이를 <strong>탐색적 데이터 분석</strong>, 즉 EDA라고 한다.</p>
<p>아이스크림 판매량 데이터가 있다면 우선 다음을 확인해야 한다.</p>
<ul>
<li>하루 평균 판매량은 얼마인가?</li>
<li>판매량은 매일 비슷한가, 크게 출렁이는가?</li>
<li>특정 날에 비정상적으로 높은 판매량이 있는가?</li>
<li>판매량이 한쪽으로 치우친 분포를 가지는가?</li>
<li>결측치나 입력 오류는 없는가?</li>
</ul>
<p>이 질문에 답하기 위해 기술통계를 사용한다.</p>
<hr />
<h2 id="평균-하나만으로는-데이터가-보이지-않는다">평균 하나만으로는 데이터가 보이지 않는다</h2>
<p>두 매장의 하루 평균 판매량이 모두 300개라고 해보자.</p>
<pre><code class="language-text">매장 A
290, 300, 305, 298, 307

매장 B
50, 150, 300, 450, 550</code></pre>
<p>두 매장의 평균은 비슷하지만 판매 패턴은 전혀 다르다.</p>
<p>매장 A는 매일 안정적으로 판매되지만, 매장 B는 날마다 큰 차이를 보인다.<br />따라서 데이터의 중심뿐 아니라 <strong>얼마나 퍼져 있는지</strong>도 함께 봐야 한다.</p>
<h2 id="평균-중앙값-최빈값">평균, 중앙값, 최빈값</h2>
<h3 id="평균">평균</h3>
<p>평균은 모든 값을 더한 뒤 데이터 개수로 나눈 값이다.</p>
<pre><code class="language-text">평균 = 모든 데이터의 합 / 데이터 개수</code></pre>
<p>모든 값을 반영한다는 장점이 있지만 이상치에 민감하다.</p>
<pre><code class="language-text">10, 12, 13, 15, 16
→ 평균 13.2
→ 중앙값 13</code></pre>
<p>마지막 값만 100으로 바꾸면 다음과 같다.</p>
<pre><code class="language-text">10, 12, 13, 15, 100
→ 평균 30
→ 중앙값 13</code></pre>
<p>데이터 대부분은 그대로인데 이상치 하나로 평균은 크게 변했다.</p>
<h3 id="중앙값">중앙값</h3>
<p>중앙값은 데이터를 크기순으로 정렬했을 때 가운데에 위치한 값이다.</p>
<p>이상치의 영향을 덜 받기 때문에 소득, 주택가격, 구매금액처럼 일부 큰 값이 존재하는 데이터에서 유용하다.</p>
<h3 id="최빈값">최빈값</h3>
<p>최빈값은 가장 자주 등장한 값이다.</p>
<pre><code class="language-text">A, A, B, B, B, C
→ 최빈값 B</code></pre>
<p>최빈값은 숫자뿐 아니라 상품 종류나 고객 등급 같은 범주형 데이터에도 사용할 수 있다.</p>
<table>
<thead>
<tr>
<th>통계량</th>
<th>의미</th>
<th>주의점</th>
</tr>
</thead>
<tbody><tr>
<td>평균</td>
<td>모든 값의 산술적 중심</td>
<td>이상치에 민감</td>
</tr>
<tr>
<td>중앙값</td>
<td>정렬했을 때 가운데 값</td>
<td>데이터 전체의 크기를 모두 반영하지는 않음</td>
</tr>
<tr>
<td>최빈값</td>
<td>가장 자주 등장한 값</td>
<td>최빈값이 없거나 여러 개일 수 있음</td>
</tr>
</tbody></table>
<p>평균과 중앙값의 차이가 크다면 데이터가 한쪽으로 치우쳤거나 이상치가 존재할 가능성이 있다.</p>
<hr />
<h2 id="데이터가-얼마나-흔들리는가">데이터가 얼마나 흔들리는가</h2>
<p>평균이 데이터의 중심을 설명한다면, 분산과 표준편차는 데이터의 퍼짐을 설명한다.</p>
<h3 id="범위">범위</h3>
<p>범위는 최댓값에서 최솟값을 뺀 값이다.</p>
<pre><code class="language-text">범위 = 최댓값 - 최솟값</code></pre>
<p>계산은 간단하지만 두 개의 값만 사용하므로 이상치에 매우 민감하다.</p>
<h3 id="분산">분산</h3>
<p>분산은 각 데이터가 평균에서 얼마나 떨어져 있는지를 제곱해 평균한 값이다.</p>
<pre><code class="language-text">분산
= 편차 제곱의 합 / 데이터 개수</code></pre>
<p>편차를 그대로 더하면 양수와 음수가 서로 상쇄될 수 있기 때문에 제곱한다.</p>
<p>표본 분산에서는 분모로 <code>n</code>이 아니라 <code>n - 1</code>을 사용한다.</p>
<pre><code class="language-text">표본 분산
= 편차 제곱의 합 / (n - 1)</code></pre>
<p>표본은 모집단의 평균을 정확히 알지 못한 채 표본평균을 기준으로 편차를 계산한다. 이 과정에서 모집단의 실제 변동성을 작게 추정하는 경향이 생기므로 <code>n - 1</code>을 사용해 이를 보정한다.</p>
<h3 id="표준편차">표준편차</h3>
<p>표준편차는 분산에 제곱근을 적용한 값이다.</p>
<pre><code class="language-text">표준편차 = 분산의 제곱근</code></pre>
<p>분산은 원래 단위가 제곱되지만 표준편차는 원래 데이터와 같은 단위를 사용한다.</p>
<pre><code class="language-text">평균 판매량: 300개
표준편차: 10개

→ 판매량이 평균 주변에 비교적 안정적으로 모여 있음</code></pre>
<pre><code class="language-text">평균 판매량: 300개
표준편차: 150개

→ 날마다 판매량의 차이가 큼</code></pre>
<p>AI 모델을 만들 때 평균만 확인해서는 안 된다.<br />입력 변수나 Target의 변동성이 지나치게 크다면 이상치, 계절성, 데이터 분포를 함께 점검해야 한다.</p>
<hr />
<h2 id="극단적인-값은-무조건-지워야-할까">극단적인 값은 무조건 지워야 할까?</h2>
<p>아이스크림 판매량 데이터에서 어느 날만 판매량이 2,000개로 기록되어 있다고 하자.</p>
<p>이 값은 다음 중 하나일 수 있다.</p>
<pre><code class="language-text">입력 오류

대규모 행사로 인한 실제 급증

특별 할인 이벤트

단체 주문

수집 시스템의 중복 기록</code></pre>
<p>따라서 이상치는 단순히 크거나 작다는 이유로 삭제하면 안 된다.</p>
<p>이상치 후보를 찾는 대표적인 방법으로 IQR을 사용할 수 있다.</p>
<pre><code class="language-text">IQR = Q3 - Q1</code></pre>
<p>여기서 Q1은 하위 25%, Q2는 중앙값, Q3는 하위 75% 지점이다.</p>
<p>이상치 후보의 일반적인 기준은 다음과 같다.</p>
<pre><code class="language-text">아래쪽 이상치 후보
&lt; Q1 - 1.5 × IQR

위쪽 이상치 후보
&gt; Q3 + 1.5 × IQR</code></pre>
<p>이 기준을 벗어났다는 것은 검토가 필요하다는 뜻이지, 반드시 삭제해야 한다는 의미는 아니다.</p>
<blockquote>
<p>이상치는 제거 대상이 아니라 먼저 원인을 확인해야 하는 데이터다.</p>
</blockquote>
<hr />
<h2 id="분포의-모양도-확인해야-한다">분포의 모양도 확인해야 한다</h2>
<p>같은 평균과 표준편차를 가진 데이터라도 분포 모양은 다를 수 있다.</p>
<h3 id="왜도">왜도</h3>
<p>왜도는 분포가 한쪽으로 얼마나 치우쳐 있는지를 나타낸다.<br />방향은 데이터가 몰린 쪽이 아니라 <strong>꼬리가 길게 늘어진 방향</strong>을 기준으로 한다.</p>
<pre><code class="language-text">양의 왜도
→ 오른쪽 꼬리가 김
→ 일부 매우 큰 값이 존재
→ 평균이 중앙값보다 커지는 경향</code></pre>
<pre><code class="language-text">음의 왜도
→ 왼쪽 꼬리가 김
→ 일부 매우 작은 값이 존재
→ 평균이 중앙값보다 작아지는 경향</code></pre>
<p>소득, 주택가격, 구매금액은 소수의 큰 값 때문에 양의 왜도를 보이는 경우가 많다.</p>
<h3 id="첨도">첨도</h3>
<p>첨도는 단순히 분포가 뾰족한 정도만을 의미하지 않는다.<br />분포의 꼬리가 얼마나 두껍고 극단적인 값이 상대적으로 얼마나 자주 나타나는지도 함께 보여준다.</p>
<pre><code class="language-text">첨도가 큼
→ 꼬리가 두꺼움
→ 극단값이 상대적으로 자주 나타남

첨도가 작음
→ 꼬리가 얇음
→ 극단값이 상대적으로 적음</code></pre>
<hr />
<h2 id="이동평균으로-추세를-확인하기">이동평균으로 추세를 확인하기</h2>
<p>판매량처럼 시간의 흐름에 따라 기록되는 데이터는 하루 단위 변동이 매우 클 수 있다.</p>
<p>이때 일정 기간의 평균을 계속 이동하며 계산하는 <strong>이동평균</strong>을 사용하면 단기적인 잡음을 줄이고 전체 추세를 확인할 수 있다.</p>
<pre><code class="language-text">1일~3일 평균
→ 첫 번째 이동평균

2일~4일 평균
→ 두 번째 이동평균

3일~5일 평균
→ 세 번째 이동평균</code></pre>
<p>기간이 너무 짧으면 잡음이 많이 남고, 너무 길면 변화에 늦게 반응한다.</p>
<p>AI 시계열 모델에서도 단순한 이동평균은 비교 기준이 되거나 추세를 추출하는 전처리 방법으로 활용된다.</p>
<hr />
<h1 id="3-서로-다른-데이터를-같은-기준에서-비교하기">3. 서로 다른 데이터를 같은 기준에서 비교하기</h1>
<p>기온, 가격, 습도, 판매량은 단위와 범위가 모두 다르다.</p>
<pre><code class="language-text">기온
10 ~ 35

가격
1,000 ~ 5,000

습도
20 ~ 100

판매량
0 ~ 2,000</code></pre>
<p>이 상태로 모델을 학습하면 값의 범위가 큰 변수가 계산에 더 강하게 반영될 수 있다.</p>
<p>이를 완화하기 위해 표준화를 사용한다.</p>
<h2 id="z-score">z-score</h2>
<p>z-score는 어떤 값이 평균으로부터 표준편차 몇 배만큼 떨어져 있는지를 나타낸다.</p>
<pre><code class="language-text">z-score
= (관측값 - 평균) / 표준편차</code></pre>
<pre><code class="language-text">z = 0
→ 평균과 같은 값

z = 1
→ 평균보다 표준편차 1만큼 큰 값

z = -2
→ 평균보다 표준편차 2만큼 작은 값</code></pre>
<p>예를 들어 영어 90점과 수학 80점만 보면 영어 점수가 더 높다.</p>
<p>하지만 시험별 평균과 표준편차가 다음과 같다면 해석이 달라진다.</p>
<pre><code class="language-text">영어
평균 85, 표준편차 10
→ z = 0.5

수학
평균 60, 표준편차 10
→ z = 2</code></pre>
<p>원점수는 영어가 높지만 집단 내 상대적인 위치는 수학이 더 높다.</p>
<p>표준화는 다음 모델에서 특히 중요하다.</p>
<ul>
<li>거리 기반 알고리즘</li>
<li>경사하강법을 사용하는 모델</li>
<li>변수 크기에 민감한 모델</li>
<li>정규화된 회귀모형</li>
</ul>
<p>반면 트리 기반 모델처럼 변수의 절대적인 스케일에 덜 민감한 알고리즘도 있다. 따라서 모든 모델에 무조건 표준화를 적용하기보다 모델의 특성과 데이터 구조를 고려해야 한다.</p>
<hr />
<h1 id="4-일부-데이터로-현실-전체를-판단할-수-있을까">4. 일부 데이터로 현실 전체를 판단할 수 있을까?</h1>
<p>우리가 가진 학습 데이터는 현실 전체가 아니다.</p>
<pre><code class="language-text">현실에서 발생할 수 있는 모든 판매 상황
→ 모집단

현재 수집한 몇 년간의 판매 기록
→ 표본</code></pre>
<p>AI 모델은 표본에서 관계를 학습한 뒤 아직 보지 못한 데이터에 적용한다.</p>
<p>따라서 가장 중요한 질문은 다음과 같다.</p>
<blockquote>
<p>현재 표본에서 찾은 관계를 현실 전체에도 적용할 수 있는가?</p>
</blockquote>
<p>이 문제를 다루는 것이 추론통계다.</p>
<hr />
<h2 id="모집단-표본-모수-통계량">모집단, 표본, 모수, 통계량</h2>
<p>모집단은 관심 대상 전체이고, 표본은 실제로 수집한 일부 데이터다.</p>
<p>모집단의 특성을 나타내는 값을 <strong>모수</strong>, 표본에서 계산한 값을 <strong>통계량</strong>이라고 한다.</p>
<pre><code class="language-text">모집단 평균
→ 모수

표본평균
→ 통계량</code></pre>
<p>우리는 모집단 전체를 알 수 없기 때문에 표본통계량을 이용해 모집단의 모수를 추정한다.</p>
<hr />
<h2 id="데이터가-많다고-항상-좋은-표본은-아니다">데이터가 많다고 항상 좋은 표본은 아니다</h2>
<p>표본 수가 많아도 특정 조건의 데이터만 과도하게 포함되면 현실을 제대로 대표하지 못한다.</p>
<p>예를 들어 아이스크림 판매량 데이터가 모두 여름철 대도시 매장에서 수집되었다면 겨울철이나 농촌 지역의 판매량을 정확히 예측하기 어렵다.</p>
<p>대표적인 표본편향에는 다음이 있다.</p>
<table>
<thead>
<tr>
<th>편향</th>
<th>의미</th>
</tr>
</thead>
<tbody><tr>
<td>선택편향</td>
<td>특정 집단이 과도하게 포함됨</td>
</tr>
<tr>
<td>응답편향</td>
<td>응답하려는 사람만 조사에 참여함</td>
</tr>
<tr>
<td>생존편향</td>
<td>살아남은 사례만 보고 실패 사례는 제외함</td>
</tr>
</tbody></table>
<p>AI에서는 데이터 편향이 그대로 모델의 예측 편향으로 이어질 수 있다.</p>
<pre><code class="language-text">편향된 학습 데이터
→ 특정 패턴을 과도하게 학습
→ 실제 환경에서 불공정하거나 부정확한 예측</code></pre>
<hr />
<h2 id="큰-수의-법칙">큰 수의 법칙</h2>
<p>같은 실험을 반복할수록 관측된 평균이 이론적인 기대값에 가까워지는 현상을 큰 수의 법칙이라고 한다.</p>
<p>동전을 10번 던졌을 때 앞면이 7번 나올 수 있다.</p>
<pre><code class="language-text">앞면 비율 70%</code></pre>
<p>하지만 동전을 매우 많이 던지면 앞면 비율은 50% 주변으로 안정되는 경향을 보인다.</p>
<p>큰 수의 법칙은 데이터가 많아질수록 평균적인 패턴이 안정되는 이유를 설명한다.</p>
<p>다만 데이터가 많아도 표본 자체가 편향되어 있다면 잘못된 평균에 더 안정적으로 가까워질 뿐이다.</p>
<hr />
<h2 id="중심극한정리">중심극한정리</h2>
<p>중심극한정리는 원래 데이터의 분포가 어떤 모양이든, 충분히 큰 표본을 반복해서 추출하면 <strong>표본평균들의 분포가 정규분포에 가까워진다</strong>는 내용이다.</p>
<pre><code class="language-text">하나의 표본
→ 표본평균 하나

여러 표본을 반복 추출
→ 여러 개의 표본평균

표본 크기가 충분히 큼
→ 표본평균들의 분포가 정규분포에 가까워짐</code></pre>
<p>여기서 정규분포에 가까워지는 것은 원본 데이터가 아니라 <strong>표본평균의 분포</strong>다.</p>
<p>이 성질 덕분에 모집단이 완벽한 정규분포가 아니더라도 평균에 대한 신뢰구간과 가설검정을 수행할 수 있다.</p>
<hr />
<h2 id="표준편차와-표준오차">표준편차와 표준오차</h2>
<p>두 개념은 이름이 비슷하지만 측정하는 대상이 다르다.</p>
<pre><code class="language-text">표준편차
→ 개별 데이터가 얼마나 흩어져 있는가?

표준오차
→ 표본에서 계산한 평균이 표본마다 얼마나 흔들리는가?</code></pre>
<p>표본평균의 표준오차는 다음과 같이 표현한다.</p>
<pre><code class="language-text">표준오차
= 표준편차 / 표본 크기의 제곱근</code></pre>
<p>표본 수가 증가하면 표준오차는 작아진다.</p>
<pre><code class="language-text">표본 수 증가
→ 표본평균의 흔들림 감소
→ 모집단 평균을 더 안정적으로 추정</code></pre>
<hr />
<h2 id="신뢰구간">신뢰구간</h2>
<p>표본평균 하나만으로 모집단 평균을 정확히 알 수는 없다.</p>
<p>따라서 하나의 값 대신 모집단 평균이 있을 것으로 기대되는 범위를 제시한다.</p>
<pre><code class="language-text">점 추정
→ 평균 판매량은 300개다.

구간 추정
→ 평균 판매량은 일정한 신뢰수준에서
  285개에서 315개 사이로 추정된다.</code></pre>
<p>신뢰구간의 기본 구조는 다음과 같다.</p>
<pre><code class="language-text">신뢰구간
= 표본평균 ± 임계값 × 표준오차</code></pre>
<p>표본 수가 많아지거나 데이터의 변동성이 작아지면 신뢰구간은 좁아진다.</p>
<p>신뢰구간은 단순히 평균 하나를 보여주는 것이 아니라 <strong>추정의 불확실성</strong>을 함께 보여준다.</p>
<blockquote>
<p><strong>68, 95, 99.7의 법칙</strong></p>
</blockquote>
<hr />
<h2 id="학습·검증·테스트-데이터">학습·검증·테스트 데이터</h2>
<p>추론통계의 관점은 데이터 분할에도 그대로 이어진다.</p>
<pre><code class="language-text">학습 데이터
→ 모델이 패턴을 학습

검증 데이터
→ 모델 구조와 설정을 선택

테스트 데이터
→ 최종 일반화 성능을 평가</code></pre>
<p>훈련 데이터에서 높은 성능을 보였다고 해서 새로운 데이터에서도 같은 성능을 낸다는 보장은 없다.</p>
<p>인공지능의 일반화는 결국 다음 문제다.</p>
<blockquote>
<p>현재 표본에서 학습한 관계를 아직 보지 못한 모집단의 데이터에도 적용할 수 있는가?</p>
</blockquote>
<hr />
<h1 id="5-변수는-정말-함께-움직이는가">5. 변수는 정말 함께 움직이는가?</h1>
<p>이제 기온과 아이스크림 판매량의 관계를 살펴보자.</p>
<p>가장 먼저 해야 할 일은 상관계수부터 계산하는 것이 아니라 <strong>산점도를 그려보는 것</strong>이다.</p>
<p>산점도에서는 기온을 X축, 판매량을 Y축에 두고 하루의 관측값을 점 하나로 표현한다.</p>
<p>산점도를 통해 다음을 확인할 수 있다.</p>
<ul>
<li>기온이 높을수록 판매량도 증가하는가?</li>
<li>점들이 직선 주변에 모여 있는가?</li>
<li>곡선 형태의 관계가 나타나는가?</li>
<li>특정 관측값이 전체 관계를 왜곡하고 있는가?</li>
</ul>
<hr />
<h2 id="공분산">공분산</h2>
<p>공분산은 두 변수가 평균으로부터 같은 방향으로 움직이는지를 확인한다.</p>
<pre><code class="language-text">공분산
= X와 Y의 편차를 곱한 값들의 평균</code></pre>
<p>기온과 판매량이 모두 평균보다 높으면 편차의 곱은 양수가 된다.<br />반대로 기온은 평균보다 높은데 판매량은 평균보다 낮으면 편차의 곱은 음수가 된다.</p>
<p>따라서 공분산이 양수면 두 변수가 같은 방향으로 움직이는 경향이 있고, 음수면 반대 방향으로 움직이는 경향이 있다.</p>
<p>하지만 공분산은 변수의 단위에 따라 값의 크기가 달라지므로 관계의 강도를 직접 비교하기 어렵다.</p>
<hr />
<h2 id="상관계수">상관계수</h2>
<p>상관계수는 공분산을 두 변수의 표준편차로 나누어 단위의 영향을 제거한 값이다.</p>
<pre><code class="language-text">상관계수
= 공분산 / (X의 표준편차 × Y의 표준편차)</code></pre>
<p>상관계수는 -1에서 1 사이의 값을 가진다.</p>
<pre><code class="language-text">r &gt; 0
→ 양의 선형관계

r &lt; 0
→ 음의 선형관계

r ≈ 0
→ 선형관계가 거의 없음

|r|이 1에 가까움
→ 강한 선형관계</code></pre>
<p>상관계수가 크다는 것은 두 변수가 강한 <strong>선형관계</strong>를 가진다는 뜻이다.</p>
<hr />
<h2 id="상관계수만-믿으면-안-되는-이유">상관계수만 믿으면 안 되는 이유</h2>
<h3 id="이상치가-관계를-바꿀-수-있다">이상치가 관계를 바꿀 수 있다</h3>
<p>하나의 이상치가 상관계수를 크게 높이거나 낮출 수 있다.</p>
<p>따라서 상관계수는 산점도와 함께 확인해야 한다.</p>
<h3 id="비선형-관계를-놓칠-수-있다">비선형 관계를 놓칠 수 있다</h3>
<p>두 변수 사이에 뚜렷한 곡선 관계가 있어도 상관계수는 0에 가깝게 나타날 수 있다.</p>
<pre><code class="language-text">상관계수 ≈ 0
→ 선형관계가 약함

상관계수 ≈ 0
≠ 아무 관계도 없음</code></pre>
<h3 id="평균-자료는-관계를-과장할-수-있다">평균 자료는 관계를 과장할 수 있다</h3>
<p>개별 데이터 대신 지역별 평균이나 월별 평균을 사용하면 잡음이 줄어들면서 실제보다 관계가 강하게 보일 수 있다.</p>
<h3 id="허위상관이-나타날-수-있다">허위상관이 나타날 수 있다</h3>
<p>시간의 흐름에 따라 함께 증가하는 두 변수는 실제 관련이 없어도 높은 상관계수를 보일 수 있다.</p>
<hr />
<h2 id="상관관계는-인과관계가-아니다">상관관계는 인과관계가 아니다</h2>
<p>아이스크림 판매량과 물놀이 사고가 함께 증가한다고 해보자.</p>
<pre><code class="language-text">아이스크림 판매량 증가
↔
물놀이 사고 증가</code></pre>
<p>아이스크림이 사고의 원인은 아니다.</p>
<p>더운 날씨라는 제3의 변수가 두 변수에 함께 영향을 주었을 가능성이 크다.</p>
<pre><code class="language-text">기온 상승
├─ 아이스크림 판매량 증가
└─ 물놀이 인구와 사고 증가</code></pre>
<p>인과관계를 주장하려면 다음을 검토해야 한다.</p>
<ul>
<li>원인이 결과보다 먼저 발생하는가?</li>
<li>X가 변할 때 Y도 함께 변하는가?</li>
<li>두 변수를 함께 설명하는 다른 변수가 없는가?</li>
<li>실험이나 적절한 통제가 이루어졌는가?</li>
</ul>
<blockquote>
<p>상관분석은 두 변수가 함께 변하는지를 보여주지만, 왜 변하는지까지 설명하지는 않는다.</p>
</blockquote>
<hr />
<h1 id="6-관계를-이용해-값을-예측하자">6. 관계를 이용해 값을 예측하자</h1>
<p>기온과 판매량 사이에 상관관계가 있다면 이를 하나의 식으로 표현해 새로운 판매량을 예측할 수 있다.</p>
<p>이때 사용하는 가장 기본적인 방법이 선형회귀다.</p>
<h2 id="단순선형회귀">단순선형회귀</h2>
<p>단순선형회귀는 하나의 독립변수로 종속변수를 설명한다.</p>
<pre><code class="language-text">예측 판매량
= 절편 + 기울기 × 기온

ŷ = b0 + b1 × x</code></pre>
<p>여기서 기울기 <code>b1</code>은 기온이 1도 증가할 때 판매량의 예측값이 평균적으로 얼마나 변하는지를 의미한다.</p>
<pre><code class="language-text">ŷ = 100 + 15 × x</code></pre>
<p>위 식에서 기울기는 15다.</p>
<pre><code class="language-text">기온이 1도 증가
→ 예측 판매량이 평균적으로 15개 증가</code></pre>
<hr />
<h2 id="왜-전체-평균만-예측하지-않을까">왜 전체 평균만 예측하지 않을까?</h2>
<p>기온 정보가 없다면 모든 날의 판매량을 전체 평균으로 예측할 수 있다.</p>
<pre><code class="language-text">모든 날
→ 평균 판매량 300개로 예측</code></pre>
<p>하지만 기온과 판매량 사이에 관계가 있다면 기온에 따라 서로 다른 평균 판매량을 예측하는 편이 더 정확하다.</p>
<pre><code class="language-text">전체 평균
→ 모든 X에 같은 예측

회귀분석
→ X값에 따라 다른 Y의 평균을 예측</code></pre>
<p>회귀선은 각 X값에 대응하는 Y의 평균적인 경향을 하나의 직선으로 근사한 것이다.</p>
<hr />
<h2 id="다중선형회귀">다중선형회귀</h2>
<p>실제 판매량은 기온 하나만으로 결정되지 않는다.</p>
<pre><code class="language-text">기온
습도
가격
요일
행사 여부</code></pre>
<p>여러 변수를 함께 사용하면 다중선형회귀가 된다.</p>
<pre><code class="language-text">ŷ
= b0
+ b1 × 기온
+ b2 × 습도
+ b3 × 가격
+ ...</code></pre>
<p>다중회귀의 계수는 다른 변수들이 동일하다고 가정한 상태에서 해석한다.</p>
<pre><code class="language-text">다른 조건이 동일할 때

기온이 1도 증가하면

판매량의 예측값은 평균적으로 b1만큼 변한다.</code></pre>
<hr />
<h2 id="잔차와-최소제곱법">잔차와 최소제곱법</h2>
<p>실제 판매량과 모델의 예측값은 항상 같지 않다.</p>
<pre><code class="language-text">실제 판매량: 350개

예측 판매량: 320개

잔차: 30개</code></pre>
<p>잔차는 실제값에서 예측값을 뺀 값이다.</p>
<pre><code class="language-text">잔차 = 실제값 - 예측값</code></pre>
<p>회귀분석은 잔차 제곱의 합이 가장 작아지는 직선을 선택한다.</p>
<pre><code class="language-text">SSE
= Σ(실제값 - 예측값)²</code></pre>
<p>잔차를 그대로 더하면 양수와 음수가 상쇄될 수 있으므로 제곱해서 합한다. 이를 최소제곱법이라고 한다.</p>
<hr />
<h2 id="평균으로의-회귀">평균으로의 회귀</h2>
<p>상관관계가 완벽하지 않다면 매우 높은 기온에 대응하는 판매량의 예측값은 기온만큼 극단적으로 높아지지 않을 수 있다.</p>
<pre><code class="language-text">매우 높은 X
→ Y도 높게 예측됨
→ 하지만 평균 쪽에 더 가까울 수 있음</code></pre>
<p>이를 평균으로의 회귀라고 한다.</p>
<hr />
<h1 id="7-회귀모형이-좋은지-평가하자">7. 회귀모형이 좋은지 평가하자</h1>
<p>회귀식을 구했다고 분석이 끝나는 것은 아니다.</p>
<p>모델이 실제값을 얼마나 잘 설명하고, 새로운 데이터에서도 안정적으로 작동하는지 확인해야 한다.</p>
<h2 id="rmse">RMSE</h2>
<p>RMSE는 잔차 제곱의 평균에 제곱근을 적용한 값이다.</p>
<pre><code class="language-text">RMSE
= √[Σ(실제값 - 예측값)² / 데이터 개수]</code></pre>
<p>RMSE는 Target과 같은 단위를 가진다.</p>
<pre><code class="language-text">RMSE가 작음
→ 실제값과 예측값의 차이가 전반적으로 작음

RMSE가 큼
→ 예측 오차가 큼</code></pre>
<p>아이스크림 판매량 모델의 RMSE가 20이라면 실제 판매량과 예측값 사이의 오차가 대략 20개 수준이라는 의미로 해석할 수 있다.</p>
<hr />
<h2 id="결정계수-r²">결정계수 R²</h2>
<p>R²는 종속변수의 전체 변동 중 모델이 설명한 비율을 나타낸다.</p>
<pre><code class="language-text">R²
= 1 - 설명하지 못한 변동 / 전체 변동</code></pre>
<pre><code class="language-text">R² = 0
→ 평균만 사용한 예측보다 설명력이 없음

R² = 0.7
→ 판매량 변동의 약 70%를 모델이 설명

R² = 1
→ 모든 관측값을 완벽하게 설명</code></pre>
<p>하지만 R²가 높다고 무조건 좋은 모델은 아니다.</p>
<ul>
<li>훈련 데이터에만 지나치게 맞춘 과적합</li>
<li>데이터 누수</li>
<li>이상치로 인한 왜곡</li>
<li>잘못된 인과해석</li>
</ul>
<p>다중회귀에서는 독립변수를 추가하면 R²가 쉽게 증가한다. 따라서 변수 개수까지 고려하는 수정 R²를 함께 확인하는 것이 좋다.</p>
<hr />
<h2 id="회귀모형-전체와-변수별-검정">회귀모형 전체와 변수별 검정</h2>
<h3 id="f-검정">F 검정</h3>
<p>F 검정은 회귀모형 전체가 종속변수를 설명하는 데 통계적으로 의미가 있는지를 확인한다.</p>
<pre><code class="language-text">귀무가설
→ 모든 독립변수의 회귀계수가 0이다.

대립가설
→ 적어도 하나의 회귀계수는 0이 아니다.</code></pre>
<h3 id="변수별-t-검정">변수별 t 검정</h3>
<p>각 독립변수의 계수가 0과 통계적으로 구분되는지를 확인한다.</p>
<p>회귀계수를 해석할 때는 다음을 함께 봐야 한다.</p>

<h2 id="잔차가-보여주는-모델의-한계">잔차가 보여주는 모델의 한계</h2>
<p>잔차는 단순한 오차가 아니다.<br />모델이 놓친 패턴과 회귀모형의 문제를 보여주는 진단 자료다.</p>
<h3 id="선형성">선형성</h3>
<p>잔차가 0 주변에 무작위로 퍼져 있다면 선형관계에 대체로 부합한다.</p>
<p>반대로 잔차에 U자형이나 S자형 패턴이 나타나면 직선으로 설명하기 어려운 비선형 관계가 있을 수 있다.</p>
<h3 id="독립성">독립성</h3>
<p>시간 순서에 따라 잔차가 연속적인 흐름을 보인다면 오차가 서로 독립적이지 않을 수 있다.</p>
<p>시계열, 공간 데이터, 반복측정 데이터에서는 특히 주의해야 한다.</p>
<h3 id="등분산성">등분산성</h3>
<p>예측값의 크기와 관계없이 잔차의 퍼짐이 비슷해야 한다.</p>
<p>잔차 그래프가 깔때기처럼 넓어지거나 좁아진다면 이분산성을 의심할 수 있다.</p>
<h3 id="정규성">정규성</h3>
<p>잔차가 평균 0을 중심으로 정규분포에 가까운지 확인한다.</p>
<p>이는 회귀계수 자체를 계산하기보다 t 검정, F 검정, 신뢰구간을 해석할 때 중요하다.</p>
<h3 id="다중공선성">다중공선성</h3>
<p>독립변수끼리 거의 같은 정보를 가지면 각 변수의 고유한 영향을 구분하기 어려워진다.</p>
<pre><code class="language-text">차량 연식
↔

마력</code></pre>
<p>다중공선성이 크면 회귀계수가 불안정해지고, 중요한 변수도 유의하지 않게 나타날 수 있다.</p>

<h1 id="8-새-모델이-정말-더-좋아졌다고-말할-수-있을까">8. 새 모델이 정말 더 좋아졌다고 말할 수 있을까?</h1>
<p>기존 모델의 정확도가 90%, 새 모델의 정확도가 91%라고 하자.</p>
<p>숫자만 보면 새 모델이 좋아 보인다.<br />하지만 테스트 데이터를 다시 뽑으면 결과가 반대로 나올 수도 있다.</p>
<p>따라서 다음을 판단해야 한다.</p>
<blockquote>
<p>관찰한 차이가 실제 개선인가, 아니면 표본의 우연한 변동인가?</p>
</blockquote>
<p>이 질문을 다루는 방법이 가설검정이다.</p>
<hr />
<h2 id="귀무가설과-대립가설">귀무가설과 대립가설</h2>
<p>귀무가설은 차이나 관계가 없다는 기본 가설이다.</p>
<pre><code class="language-text">H0
두 모델의 실제 성능에는 차이가 없다.</code></pre>
<p>대립가설은 확인하고 싶은 가설이다.</p>
<pre><code class="language-text">H1
두 모델의 실제 성능에는 차이가 있다.</code></pre>
<p>가설검정은 귀무가설이 참이라고 가정한 상태에서 현재와 같은 결과가 나타나는 것이 얼마나 드문지를 판단한다.</p>
<hr />
<h2 id="p-value">p-value</h2>
<p>p-value는 다음과 같이 이해할 수 있다.</p>
<blockquote>
<p>귀무가설이 참이라고 가정했을 때, 현재 관찰한 결과 이상으로 극단적인 결과가 나타날 확률</p>
</blockquote>
<p>유의수준을 0.05로 정했다면 다음처럼 판단한다.</p>
<pre><code class="language-text">p-value &lt; 0.05
→ 귀무가설 기각
→ 통계적으로 유의한 차이가 있다고 판단</code></pre>
<pre><code class="language-text">p-value ≥ 0.05
→ 귀무가설을 기각할 근거가 부족</code></pre>
<p>하지만 p-value는 자주 잘못 해석된다.</p>
<pre><code class="language-text">p-value
≠ 귀무가설이 참일 확률

p-value가 큼
≠ 귀무가설이 참이라는 증명

통계적으로 유의함
≠ 현실적으로 중요한 차이</code></pre>
<p>표본이 매우 크면 아주 작은 차이도 통계적으로 유의하게 나타날 수 있다.</p>
<p>따라서 p-value와 함께 <strong>효과크기</strong>와 <strong>신뢰구간</strong>을 확인해야 한다.</p>
<hr />
<h2 id="단측검정과-양측검정">단측검정과 양측검정</h2>
<p>단측검정은 차이의 방향까지 가설에 포함한다.</p>
<pre><code class="language-text">H1
새 모델의 성능이 기존 모델보다 높다.</code></pre>
<p>양측검정은 방향을 정하지 않고 차이의 존재 자체를 확인한다.</p>
<pre><code class="language-text">H1
새 모델과 기존 모델의 성능이 서로 다르다.</code></pre>
<p>검정 방향은 결과를 본 뒤 유리하게 바꾸는 것이 아니라 분석 전에 정해야 한다.</p>
<hr />
<h2 id="제1종-오류와-제2종-오류">제1종 오류와 제2종 오류</h2>
<h3 id="제1종-오류">제1종 오류</h3>
<p>실제로 차이가 없는데 차이가 있다고 판단하는 오류다.</p>
<pre><code class="language-text">참인 귀무가설을 기각</code></pre>
<h3 id="제2종-오류">제2종 오류</h3>
<p>실제로 차이가 있는데 차이가 없다고 판단하는 오류다.</p>
<pre><code class="language-text">거짓인 귀무가설을 기각하지 못함</code></pre>
<p>AI 서비스에서는 어떤 오류가 더 치명적인지에 따라 평가 기준이 달라진다.</p>
<pre><code class="language-text">질병 탐지 모델

환자를 정상으로 판단
→ 실제 Positive를 놓침
→ 제2종 오류가 매우 중요할 수 있음</code></pre>
<pre><code class="language-text">스팸 탐지 모델

정상 메일을 스팸으로 판단
→ 제1종 오류가 중요한 문제가 될 수 있음</code></pre>
<hr />
<h2 id="t검정-카이제곱-검정-anova">t검정, 카이제곱 검정, ANOVA</h2>
<h3 id="t검정">t검정</h3>
<p>두 집단의 평균 차이가 자연스러운 표본 변동에 비해 충분히 큰지를 확인한다.</p>
<pre><code class="language-text">t 통계량
= 평균 차이 / 평균 차이의 표준오차</code></pre>
<h3 id="카이제곱-검정">카이제곱 검정</h3>
<p>범주형 변수의 관측 빈도와 기대 빈도의 차이를 분석한다.</p>
<pre><code class="language-text">성별과 상품 선호가 관련 있는가?

지역과 서비스 가입 여부가 관련 있는가?</code></pre>
<h3 id="anova">ANOVA</h3>
<p>세 집단 이상에서 평균 차이가 존재하는지 확인한다.</p>
<pre><code class="language-text">F 통계량
= 집단 사이의 변동 / 집단 내부의 변동</code></pre>
<p>집단 사이의 차이가 각 집단 내부에서 자연스럽게 나타나는 차이보다 충분히 크면 집단 평균이 모두 같다고 보기 어려워진다.</p>
<hr />
<h2 id="p-hacking">p-hacking</h2>
<p>통계적으로 유의한 결과가 나올 때까지 분석 방법을 바꾸는 행위를 p-hacking이라고 한다.</p>
<pre><code class="language-text">유의하지 않자 단측검정으로 변경

일부 데이터만 선택적으로 제거

여러 변수 중 유의한 결과만 보고

분석을 반복한 뒤 성공한 결과만 발표</code></pre>
<p>이를 방지하려면 가설과 분석 방법을 미리 정하고, 효과크기와 신뢰구간을 함께 제시하며, 전체 분석 과정을 투명하게 기록해야 한다.</p>
<hr />
<h1 id="9-분류모델의-성능도-통계적으로-보자">9. 분류모델의 성능도 통계적으로 보자</h1>
<p>아이스크림 판매량처럼 숫자를 예측하는 문제는 회귀문제다.<br />반면 스팸 여부, 질병 여부, 이탈 여부처럼 범주를 예측하는 문제는 분류문제다.</p>
<p>분류모델에서는 예측 결과를 다음 네 가지로 나눈다.</p>
<table>
<thead>
<tr>
<th>실제 / 예측</th>
<th>Positive 예측</th>
<th>Negative 예측</th>
</tr>
</thead>
<tbody><tr>
<td>실제 Positive</td>
<td>TP</td>
<td>FN</td>
</tr>
<tr>
<td>실제 Negative</td>
<td>FP</td>
<td>TN</td>
</tr>
</tbody></table>
<h2 id="정확도">정확도</h2>
<p>전체 예측 중 올바르게 예측한 비율이다.</p>
<pre><code class="language-text">정확도
= 올바른 예측 수 / 전체 예측 수</code></pre>
<p>하지만 클래스가 불균형하면 정확도만으로 모델을 평가하기 어렵다.</p>
<p>예를 들어 정상 거래가 99%, 이상 거래가 1%인 데이터에서 모든 거래를 정상으로 예측해도 정확도는 99%가 된다.</p>
<hr />
<h2 id="정밀도와-재현율">정밀도와 재현율</h2>
<p>정밀도는 Positive라고 예측한 결과가 얼마나 정확한지를 나타낸다.</p>
<pre><code class="language-text">정밀도
= TP / (TP + FP)</code></pre>
<p>재현율은 실제 Positive를 얼마나 놓치지 않고 찾아냈는지를 나타낸다.</p>
<pre><code class="language-text">재현율
= TP / (TP + FN)</code></pre>
<p>스팸 필터에서는 정상 메일을 스팸으로 분류하지 않는 정밀도가 중요할 수 있고, 질병 탐지에서는 환자를 놓치지 않는 재현율이 중요할 수 있다.</p>
<h2 id="f1-score">F1-score</h2>
<p>F1-score는 정밀도와 재현율의 조화평균이다.</p>
<pre><code class="language-text">F1-score
= 2 × 정밀도 × 재현율 / (정밀도 + 재현율)</code></pre>
<p>두 지표를 균형 있게 평가할 때 사용한다.</p>
<hr />
<h2 id="임계값에-따라-결과가-달라진다">임계값에 따라 결과가 달라진다</h2>
<p>분류모델은 보통 확률을 출력한 뒤 특정 기준을 넘으면 Positive로 분류한다.</p>
<pre><code class="language-text">예측 확률 ≥ 임계값
→ Positive

예측 확률 &lt; 임계값
→ Negative</code></pre>
<p>임계값을 낮추면 더 많은 사례를 Positive로 판단한다.</p>
<pre><code class="language-text">재현율 증가 가능
거짓 양성 증가 가능</code></pre>
<p>임계값을 높이면 Positive 판정이 더 엄격해진다.</p>
<pre><code class="language-text">정밀도 증가 가능
실제 Positive를 놓칠 가능성 증가</code></pre>
<p>따라서 임계값은 0.5로 고정하기보다 서비스에서 어떤 오류를 더 중요하게 보는지에 따라 결정해야 한다.</p>
<hr />
<h1 id="10-과적합을-편향과-분산으로-이해하기">10. 과적합을 편향과 분산으로 이해하기</h1>
<p>모델이 학습 데이터에서는 매우 잘 맞지만 새로운 데이터에서는 성능이 떨어지는 현상을 과적합이라고 한다.</p>
<p>이를 편향과 분산 관점에서 이해할 수 있다.</p>
<h2 id="편향이-큰-모델">편향이 큰 모델</h2>
<p>모델이 지나치게 단순하여 데이터의 관계를 충분히 학습하지 못한다.</p>
<pre><code class="language-text">훈련 성능이 낮음
테스트 성능도 낮음
→ 과소적합 가능성</code></pre>
<h2 id="분산이-큰-모델">분산이 큰 모델</h2>
<p>훈련 데이터의 작은 변화에도 모델 결과가 크게 달라진다.</p>
<pre><code class="language-text">훈련 성능은 매우 높음
테스트 성능은 낮음
→ 과적합 가능성</code></pre>
<p>좋은 모델은 편향과 분산 사이에서 균형을 찾아야 한다.</p>
<p>통계적으로 보면 학습 데이터는 하나의 표본이다.<br />표본이 조금 달라질 때마다 모델의 결과가 크게 바뀐다면 모델의 분산이 크다고 볼 수 있다.</p>

<h1 id="마무리">마무리</h1>
<p>인공지능은 데이터를 입력하면 정답을 만들어내는 마법 같은 장치가 아니다.</p>
<p>현실에서 수집한 일부 데이터를 바탕으로 반복되는 관계를 학습하고, 그 관계를 아직 보지 못한 데이터에 적용하는 기술이다.</p>
<p>따라서 인공지능을 이해하려면 모델의 구조만큼이나 데이터를 바라보는 통계적 관점이 필요하다.</p>
<pre><code class="language-text">변수 이해
→ 무엇을 측정하고 예측할지 정의한다.

기술통계
→ 데이터의 중심, 퍼짐, 형태를 이해한다.

확률과 추론
→ 표본으로 현실 전체를 어디까지 설명할 수 있는지 판단한다.

상관분석
→ 두 변수가 함께 움직이는 방향과 강도를 확인한다.

회귀분석
→ 변수 관계를 이용해 결과를 설명하고 예측한다.

가설검정
→ 관찰한 차이나 개선이 우연인지 판단한다.

모델 평가
→ 예측 성능과 일반화 가능성을 검증한다.</code></pre>
<blockquote>
<p><strong>통계학은 인공지능과 별개의 선행과목이 아니다.<br />인공지능이 데이터를 이해하고, 학습 결과를 평가하며, 예측의 한계를 판단하는 기초 언어다.</strong></p>
</blockquote>
<p>통계적 사고를 익히면 모델의 결과를 단순히 받아들이는 데서 그치지 않고 다음 질문을 던질 수 있게 된다.</p>
<pre><code class="language-text">이 데이터는 현실을 잘 대표하는가?

이 관계는 이상치나 우연에 의한 것은 아닌가?

이 성능 향상은 실제로 의미가 있는가?

이 모델은 새로운 데이터에서도 잘 작동할 수 있는가?</code></pre>
<p>그리고 바로 이 질문을 할 수 있는 능력이 인공지능을 더 정확하게 이해하고 활용하는 출발점이다.</p>
