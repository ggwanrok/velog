<p>데이터에서 특정 값을 찾는 가장 단순한 방법은 처음부터 하나씩 확인하는 것이다.</p>
<pre><code class="language-text">[1, 3, 5, 7, 9, 11, 13]</code></pre>
<p>여기서 <code>11</code>을 찾는다면,</p>
<pre><code class="language-text">1 → 3 → 5 → 7 → 9 → 11</code></pre>
<p>과 같이 앞에서부터 확인할 수 있다.</p>
<p>이를 <strong>선형 탐색(Linear Search)</strong>이라고 하며, 데이터가 <code>N</code>개라면 최악의 경우 <code>N</code>개의 데이터를 모두 확인해야 한다.</p>
<p>시간 복잡도는</p>
<pre><code class="language-text">O(N)</code></pre>
<p>이다.</p>
<p>하지만 데이터가 <strong>정렬되어 있다면</strong> 굳이 처음부터 하나씩 확인할 필요가 없다.</p>
<hr />
<h2 id="이분-탐색">이분 탐색</h2>
<p><strong>이분 탐색(Binary Search)</strong>은 탐색 범위의 가운데 값을 확인하고, 찾고자 하는 값이 어느 쪽에 존재하는지를 판단하여 <strong>탐색 범위를 절반씩 줄여가는 알고리즘</strong>이다.</p>
<p>예를 들어 다음과 같이 정렬된 데이터에서 <code>11</code>을 찾는다고 해보자.</p>
<pre><code class="language-text">[1, 3, 5, 7, 9, 11, 13]</code></pre>
<p>먼저 전체 범위의 가운데 값을 확인한다.</p>
<pre><code class="language-text">[1, 3, 5, 7, 9, 11, 13]
          ↑
         mid</code></pre>
<p>가운데 값은 <code>7</code>이다.</p>
<p>우리가 찾으려는 값 <code>11</code>은 <code>7</code>보다 크다.</p>
<p>그리고 데이터가 정렬되어 있기 때문에 <code>7</code>보다 왼쪽에 있는 값들은 더 이상 확인할 필요가 없다.</p>
<pre><code class="language-text">[1, 3, 5, 7]  → 제거

[9, 11, 13]    → 다음 탐색 범위</code></pre>
<p>다시 남아 있는 범위의 가운데 값을 확인한다.</p>
<pre><code class="language-text">[9, 11, 13]
     ↑
    mid</code></pre>
<p>이번에는 바로 <code>11</code>을 찾을 수 있다.</p>
<p>이처럼 이분 탐색은 매 탐색마다 전체 데이터 중 절반을 버릴 수 있다.</p>
<hr />
<h2 id="left-right-mid">left, right, mid</h2>
<p>이분 탐색에서는 보통 세 개의 값을 이용해 현재 탐색 범위를 표현한다.</p>
<pre><code class="language-cpp">int left = 0;
int right = arr.size() - 1;</code></pre>
<p><code>left</code>는 탐색 범위의 시작점이고,</p>
<p><code>right</code>는 탐색 범위의 끝점이다.</p>
<p>그리고 두 값의 가운데를 구한다.</p>
<pre><code class="language-cpp">int mid = (left + right) / 2;</code></pre>
<p>구조를 표현하면 다음과 같다.</p>
<pre><code class="language-text">left         mid          right
 ↓            ↓             ↓
[1, 3, 5, 7, 9, 11, 13, 15, 17]</code></pre>
<p>가운데 값을 기준으로 원하는 값이 오른쪽에 존재한다면</p>
<pre><code class="language-cpp">left = mid + 1;</code></pre>
<p>왼쪽 범위를 버린다.</p>
<p>반대로 원하는 값이 왼쪽에 존재한다면</p>
<pre><code class="language-cpp">right = mid - 1;</code></pre>
<p>오른쪽 범위를 버린다.</p>
<p>이를 반복한다.</p>
<pre><code class="language-cpp">while(left &lt;= right) {
    int mid = (left + right) / 2;

    if(arr[mid] == target) {
        return mid;
    }

    if(arr[mid] &lt; target) {
        left = mid + 1;
    }
    else {
        right = mid - 1;
    }
}</code></pre>
<p>이분 탐색에서 중요한 것은 코드 자체보다는 <strong>왜 한쪽 범위를 통째로 버릴 수 있는가</strong>이다.</p>
<p>그 근거는 데이터가 정렬되어 있기 때문이다.</p>
<pre><code class="language-text">arr[mid] &lt; target</code></pre>
<p>이라면 <code>mid</code>보다 왼쪽에 있는 값들은 전부 <code>arr[mid]</code>보다 작거나 같다.</p>
<p>따라서 그 영역에는 <code>target</code>이 존재할 수 없다.</p>
<p>그래서 과감하게 탐색 대상에서 제외할 수 있다.</p>
<hr />
<h2 id="olog-n">O(log N)</h2>
<p>이분 탐색은 탐색할 때마다 범위가 절반으로 감소한다.</p>
<p>예를 들어 데이터가 16개라면</p>
<pre><code class="language-text">16
↓
8
↓
4
↓
2
↓
1</code></pre>
<p>약 4번의 탐색이면 범위를 하나까지 줄일 수 있다.</p>
<p>데이터가 1,024개여도</p>
<pre><code class="language-text">1024
512
256
128
64
32
16
8
4
2
1</code></pre>
<p>약 10번이면 충분하다.</p>
<p>즉,</p>
<pre><code class="language-text">N
N / 2
N / 4
N / 8
...
1</code></pre>
<p>의 형태로 탐색 범위가 줄어든다.</p>
<p>이를 수식으로 보면</p>
<pre><code class="language-text">N / 2^k = 1

N = 2^k

k = log₂N</code></pre>
<p>이므로 이분 탐색의 시간 복잡도는</p>
<pre><code class="language-text">O(log N)</code></pre>
<p>이 된다.</p>
<p><code>O(N)</code>인 선형 탐색과 비교하면 데이터의 크기가 커질수록 차이가 크게 벌어진다.</p>
<hr />
<h2 id="파라메트릭-서치">파라메트릭 서치</h2>
<p>이분 탐색을 처음 배우면 보통</p>
<blockquote>
<p>정렬된 배열에서 값을 빠르게 찾는 알고리즘</p>
</blockquote>
<p>이라고 생각하기 쉽다.</p>
<p>물론 맞는 설명이다.</p>
<p>하지만 이분 탐색을 조금 더 일반적으로 바라보면,</p>
<blockquote>
<p><strong>어떤 기준을 중심으로 한쪽 영역을 확실하게 버릴 수 있다면 탐색 범위를 계속 절반으로 줄일 수 있다.</strong></p>
</blockquote>
<p>라고 볼 수 있다.</p>
<p>여기서 문제를 바라보는 시선을 바꿔 효율적으로 풀이를 시도해볼 수 있다.</p>
<blockquote>
<p>예를 들어, 프로그래머스의 '입국심사' 문제의 경우
[입국심사관들의 소요시간, 입국심사 대상자의 수]를 기반으로 [완료되는 시간]을 구하는 문제지만,
이를 파라메트릭 서치를 통해 [k분이면 해결 가능?]의 시선으로 바라볼 수 있고,
k분이라는 절대적인 수치는 이분탐색으로 활용할 수 있는 정보가 된다.</p>
</blockquote>
<hr />
<h3 id="적용-예시---입국심사">적용 예시 - 입국심사</h3>
<pre><code>#include &lt;string&gt;
#include &lt;vector&gt;
#include &lt;algorithm&gt;
#define ll long long
using namespace std;

long long solution(int n, vector&lt;int&gt; times) {
    long long answer = 0;

    ll left, right;
    left = 1;
    right = 1;
    for(ll i : times){
        right = max(right, i); 
    }
    right *= n;


    while(left &lt;= right){
        ll mid = (left + right) / 2;
        ll cur_res = 0;
        for(auto i : times){
            cur_res += mid/i;
        }
        if(cur_res &gt;= n){
            answer = mid;
            right = mid-1;
        }
        else{
            left = mid+1;
        }
    }

    return answer;
}</code></pre><p>이 코드에서 중요한 것은 구현보다 <strong>탐색 대상을 어떻게 설정했는가</strong>이다.</p>
<p>사람들의 배치 경우를 탐색하는 것이 아니라,</p>
<pre><code class="language-text">시간 → 처리 가능한 사람 수</code></pre>
<p>라는 단조 관계를 만들고 <strong>시간 자체를 이분 탐색</strong>했다.</p>
<hr />
<h1 id="정리">정리</h1>
<p>이분 탐색은 단순히 정렬된 배열에서 특정 값을 찾는 알고리즘으로만 볼 필요는 없다.</p>
<p>핵심은 다음과 같다.</p>
<pre><code class="language-text">1. 탐색 범위를 정한다.

2. 가운데 값 mid를 확인한다.

3. mid를 기준으로 어느 한쪽은
   정답이 될 수 없다는 것을 판단한다.

4. 해당 영역을 제거한다.

5. 이를 반복한다.</code></pre>
<p>이 과정에서 매번 탐색 범위가 절반으로 줄어들기 때문에 <code>O(log N)</code>이라는 매우 빠른 탐색 성능을 얻을 수 있다.</p>
<p>그리고 실제 알고리즘 문제에서는</p>
<pre><code class="language-text">정렬된 배열에서 값 찾기</code></pre>
<p>뿐만 아니라</p>
<pre><code class="language-text">가능한 최소 시간
가능한 최대 크기
조건을 만족하는 최소값
조건을 만족하는 최대값</code></pre>
<p>처럼 <strong>정답이 존재하는 범위에서 경계를 찾는 방식</strong>으로도 자주 활용된다.</p>
