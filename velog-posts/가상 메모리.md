<p>프로그램을 실행하면 프로세스는 메모리를 사용한다.</p>
<p>흔히 프로세스의 메모리 구조를 다음과 같이 표현한다.</p>
<pre><code class="language-text">높은 주소
┌─────────────────────┐
│        Stack        │
│          ↓          │
│                     │
│          ↑          │
│        Heap         │
├─────────────────────┤
│        Data         │
├─────────────────────┤
│     Text(Code)      │
└─────────────────────┘
낮은 주소</code></pre>
<p>처음 이 그림을 보면 실제 RAM이 <code>Code</code>, <code>Data</code>, <code>Heap</code>, <code>Stack</code>으로 나뉘어 있다고 생각하기 쉽다.</p>
<p>하지만 이 구조는 물리 메모리 자체의 배치가 아니라 <strong>프로세스가 바라보는 주소 공간(Address Space)</strong> 이다.</p>
<p>프로세스는 자신만의 메모리 공간이 존재한다고 생각하고 실행된다. 실제 데이터가 물리 메모리의 어디에 존재하는지는 운영체제가 별도로 관리한다.</p>
<hr />
<h2 id="주소-공간">주소 공간</h2>
<p>초기 시스템에서는 물리 메모리에 운영체제와 하나의 실행 프로그램이 존재하는 단순한 구조를 사용할 수 있었다.</p>
<p>하지만 여러 프로세스를 동시에 메모리에 올리는 멀티프로그래밍이 등장하면서 메모리 관리가 복잡해졌다. 각각의 프로세스를 어디에 배치할지 결정해야 하고, 서로의 메모리를 침범하지 못하도록 보호할 필요도 생겼다.</p>
<p>이를 위해 프로세스에게 실제 물리 메모리를 그대로 보여주는 대신 <strong>주소 공간이라는 추상화된 메모리 구조</strong>를 제공한다.</p>
<pre><code class="language-text">Process A                    Process B

Virtual Address Space       Virtual Address Space

┌─────────────┐             ┌─────────────┐
│   Stack     │             │   Stack     │
│     ...     │             │     ...     │
│   Heap      │             │   Heap      │
│   Data      │             │   Data      │
│   Text      │             │   Text      │
└─────────────┘             └─────────────┘</code></pre>
<p>각 프로세스는 자신의 주소 공간만 바라본다.</p>
<p>이렇게 프로그램이 바라보는 메모리와 실제 물리 메모리를 분리하는 것이 <strong>가상 메모리(Virtual Memory)</strong> 의 핵심이다.</p>
<hr />
<h2 id="가상-주소와-물리-주소">가상 주소와 물리 주소</h2>
<p>프로세스가 사용하는 주소를 <strong>가상 주소(Virtual Address)</strong>, 실제 RAM에서의 주소를 <strong>물리 주소(Physical Address)</strong> 라고 한다.</p>
<pre><code class="language-text">Process
   │
   │ Virtual Address
   ▼
Virtual Address Space
   │
   │ Address Translation
   ▼
Physical Address
   │
   ▼
Physical Memory</code></pre>
<p>예를 들어 두 프로세스가 똑같이 <code>0x1000</code>이라는 가상 주소를 사용한다고 하더라도 실제로는 서로 다른 물리 메모리를 가리킬 수 있다.</p>
<pre><code class="language-text">Process A                  Process B

VA 0x1000                  VA 0x1000
    │                          │
    ▼                          ▼
Frame 3                    Frame 8</code></pre>
<p>따라서 <code>0x1000</code>이라는 가상 주소 자체만 가지고는 실제 RAM의 위치를 알 수 없다.</p>
<p>어느 프로세스의 주소 공간에 속한 주소인지, 그리고 해당 주소가 물리 메모리 어디에 연결되어 있는지를 함께 알아야 한다.</p>
<p>프로세스마다 별도의 페이지 테이블을 가지고 자신의 가상 주소 공간을 구성하기 때문에 이런 구조가 가능하다.</p>
<hr />
<h2 id="paging">Paging</h2>
<p>가상 주소와 물리 주소의 관계를 관리하기 위해 메모리를 일정한 크기의 단위로 나눈다.</p>
<p>가상 메모리의 단위를 <strong>Page</strong>, 물리 메모리의 대응 단위를 <strong>Page Frame</strong>이라고 한다.</p>
<pre><code class="language-text">Virtual Memory              Physical Memory

Page 0 ───────────────────→ Frame 4
Page 1 ───────────────────→ Frame 1
Page 2 ───────────────────→ Frame 7
Page 3 ───────────────────→ Frame 3</code></pre>
<p>여기서 중요한 점은 <strong>가상 메모리에서 연속된 페이지가 물리 메모리에서도 연속될 필요가 없다는 것</strong>이다.</p>
<p>프로세스 입장에서는</p>
<pre><code class="language-text">Page 0
Page 1
Page 2
Page 3</code></pre>
<p>처럼 연속적인 공간을 사용하지만 실제 RAM에서는 서로 다른 위치에 흩어져 있을 수 있다.</p>
<p>이 때문에 프로세스에게 연속적인 주소 공간을 제공하면서도 실제 물리 메모리는 더 유연하게 사용할 수 있다. 실행 프로그램의 text, data 등의 페이지 역시 물리 메모리의 서로 다른 프레임에 적재될 수 있다.</p>
<hr />
<h2 id="page-table">Page Table</h2>
<p>그렇다면 가상 페이지가 물리 메모리의 어느 프레임에 있는지는 어떻게 찾을까.</p>
<p>그 관계를 관리하는 것이 <strong>Page Table</strong>이다.</p>
<pre><code class="language-text">Page Table

Virtual Page       Physical Frame
---------------------------------
Page 0        →    Frame 4
Page 1        →    Frame 1
Page 2        →    Frame 7
Page 3        →    Frame 3</code></pre>
<p>프로세스가 특정 가상 주소를 사용하면 해당 주소가 속한 가상 페이지를 기준으로 Page Table을 확인해 대응되는 물리 페이지를 찾는다.</p>
<p>주소를 개념적으로 나누면 다음과 같이 생각할 수 있다.</p>
<pre><code class="language-text">Virtual Address

┌───────────────────────┬──────────────┐
│ Virtual Page Number   │    Offset    │
└───────────────────────┴──────────────┘
             │
             │ Page Table
             ▼
┌───────────────────────┬──────────────┐
│ Physical Frame Number │    Offset    │
└───────────────────────┴──────────────┘

Physical Address</code></pre>
<p>페이지 자체의 위치는 바뀌지만 <strong>페이지 내부에서의 위치인 Offset은 유지된다.</strong></p>
<p>결국 주소 변환은 크게</p>
<pre><code class="language-text">Virtual Page
     ↓
Page Table
     ↓
Physical Frame</code></pre>
<p>의 관계를 찾는 과정이라고 볼 수 있다.</p>
<hr />
<h2 id="page-fault">Page Fault</h2>
<p>가상 주소에 대응되는 페이지가 항상 현재 물리 메모리에 존재하는 것은 아니다.</p>
<p>프로세스가 어떤 페이지에 접근했는데 현재 필요한 페이지를 사용할 수 없는 경우 <strong>Page Fault</strong>가 발생한다.</p>
<pre><code class="language-text">가상 주소 접근
      ↓
Page Table 확인
      ↓
필요한 Page가 현재 없음
      ↓
Page Fault
      ↓
운영체제 처리</code></pre>
<p><code>Fault</code>라는 이름 때문에 무조건 프로그램 오류처럼 보이지만 Page Fault 자체가 반드시 비정상적인 상황을 의미하는 것은 아니다.</p>
<p>필요한 페이지를 물리 메모리에 준비하고 페이지 테이블을 갱신한 뒤 다시 접근을 진행하는 것 역시 가상 메모리 관리 과정에서 발생할 수 있다.</p>
<hr />
<h2 id="linux에서-주소-공간-확인하기">Linux에서 주소 공간 확인하기</h2>
<p>Linux에서는 실행 중인 프로세스의 메모리 매핑을 확인할 수 있다.</p>
<pre><code class="language-bash">cat /proc/&lt;pid&gt;/maps</code></pre>
<p>또는</p>
<pre><code class="language-bash">pmap &lt;pid&gt;</code></pre>
<p>를 사용할 수 있다.</p>
<p>출력에는 다음과 같이 특정 주소 범위와 접근 권한, 매핑된 실행 파일이나 라이브러리 등이 나타난다.</p>
<pre><code class="language-text">08048000-0804e000 r-xp ... /sbin/init
0804e000-08050000 rw-p ... /sbin/init

40000000-40016000 r-xp ... /lib/ld-2.2.2.so
40024000-4014a000 r-xp ... /lib/libc.so</code></pre>
<p>여기서 앞의 주소 범위는 해당 프로세스의 <strong>가상 주소 범위</strong>다.</p>
<p>즉 <code>Text / Data / Heap / Stack</code>으로 설명했던 주소 공간을 실제 실행 중인 프로세스에서도 메모리 매핑 형태로 확인할 수 있다.</p>
<hr />
<h1 id="정리">정리</h1>
<p>가상 메모리를 단순히</p>
<blockquote>
<p>RAM이 부족할 때 디스크를 사용하는 기술</p>
</blockquote>
<p>이라고 이해하면 핵심을 놓치게 된다.</p>
<p>가상 메모리의 출발점은 <strong>프로세스가 사용하는 주소와 실제 물리 메모리 주소를 분리하는 것</strong>이다.</p>
<pre><code class="language-text">Process
   │
   ▼
Virtual Address
   │
   ▼
Virtual Address Space
   │
   ▼
Page Table
   │
   ▼
Physical Address
   │
   ▼
Physical Memory</code></pre>
<p>프로세스는 자신만의 가상 주소 공간을 기준으로 실행되고, Page Table을 통해 가상 페이지와 실제 물리 페이지의 관계가 관리된다.</p>
<p>덕분에 가상 주소 공간에서는 연속된 메모리가 실제 RAM에서는 흩어져 있을 수 있고, 서로 다른 프로세스가 동일한 가상 주소를 사용하더라도 서로 다른 물리 메모리를 사용할 수 있다.</p>
<p>그리고 우리가 흔히 배우는 <code>Text</code>, <code>Data</code>, <code>Heap</code>, <code>Stack</code> 역시 결국 <strong>이 가상 주소 공간 위에 구성되는 영역</strong>이다.</p>
